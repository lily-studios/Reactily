# Documentation Authoring

Reactily's website reads the Markdown files in `reactily-website/src/content/`. Its API reference is **not** generated by Moonwave at runtime.

## Source of truth

The release's public exports are declared in `scripts/init.luau` and shipped in the `Reactily.rbxm` ModuleScript. Use that public API and its referenced Luau modules when documenting method names, return types, event callbacks, and ownership.

For Reactily v2.1.0, public top-level functions generally use camelCase (such as `Reactily.createRoot` and `Reactily.useState`). Module namespace methods and owned-handle methods use their exported PascalCase names (such as `Reactily.Layout.Grid`, `Root.Delete`, and `Animation.Play`). The root's `render` method is specifically lowercase: `Root.render`.

Roblox Instance properties such as `BackgroundColor3`, `Size`, `Position`, and supported event properties such as `OnActivated` retain PascalCase.

## Write an API page

Put an API page under the matching `src/content/api/` category. Keep its existing `title: Reactily.apiName` frontmatter aligned with the exact public export. Use real Luau syntax and verified signatures, not guessed internal type names.

````markdown
---
title: Reactily.createRoot
description: Mounts a Reactily tree under a Roblox Instance.
---

## Usage

```luau
local Root = Reactily.createRoot(PlayerGui)
Root.render(Element)
Root.Delete()
```
````

Describe ownership and cleanup for returned handles. Update examples when their signatures change.

## Published versions

Published documentation is snapshotted from the **exact Git release tag**. Changing Markdown on `main` does not rewrite an existing release archive. To make newer documentation available under a new tag, include the Markdown changes in that release's commit before publishing it.

## Checks

Run `npm run validate:api` and `npm run validate:links` from `reactily-website` to catch missing public API pages and broken links. These checks do not replace verifying methods and examples against the shipped RBXM.
