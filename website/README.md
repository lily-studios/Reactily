# Reactily Documentation Site

A small documentation website for Reactily powered by **Moonwave** and **Docusaurus**.

Moonwave runs the Docusaurus documentation site. The Reactily API reference is maintained as Markdown under `docs/api/`.

## Requirements

- Node.js 20+
- npm
- Git

## Run locally
```bash
npm install
npm run dev
```
Moonwave runs the Docusaurus site. The public API lives only under `docs/api/`, so there is one API section.

## Build
```bash
npm run build
```
The static output is written to `build/`.

## GitHub Pages

A sample workflow is included at:
```text
.github/workflows/docs.yml
```
If this docs project lives in `Reactily/website`, update the workflow's working directory and artifact path as noted in the workflow comments.

## Documentation layout

Normal documentation stays together.

Only the public function API is separated:
```text
docs/
├── intro.md
├── getting-started.md
├── concepts/
├── guides/
├── reference/
└── api/
    ├── hooks/
    ├── state/
    ├── bindings/
    ├── signals/
    ├── animation/
    ├── typed-creators/
    └── ...
```
Each public `Reactily.*` function has its own page under `docs/api/`.

Reactily examples use `typescript` fenced code blocks for visible Prism syntax coloring while keeping the displayed source unchanged.

## Design reference

The site layout is intentionally inspired by the structure of the Cmdr documentation website:

- simple product-first landing page
- Get Started + API Documentation actions
- short feature explanations
- compact documentation sidebar
- separate API reference
- simple Learn / Project footer links

Reactily keeps its own branding, content, API organization, and color system.

## API structure

There is one API section in the Docs sidebar. Its landing page is generated by Docusaurus at `/docs/api`.

There are no physical `docs/api/index.md` or per-category `index.md` files. Category overview pages are generated by Docusaurus, which prevents duplicate API/category pages.

Reactily code examples use `typescript` code fences for syntax coloring.

## GitHub and release navigation

The site has exactly two GitHub-related navbar actions:

- `GitHub` → `https://github.com/lily-studios/Reactily`
- `Release` → live GitHub latest-release label and URL

The homepage and footer do not repeat GitHub, Issues, Source, or Releases links.

## Code highlighting

Reactily code examples use `typescript` fenced blocks for colored Docusaurus/Prism syntax highlighting.

The displayed code content is still Reactily/Luau code; only the visual syntax-highlighting language is TypeScript.

## Live release button

The navbar release label is not hard-coded.

On page load, `.moonwave/static/live-release.js` requests:
```text
https://api.github.com/repos/lily-studios/Reactily/releases/latest
```
It reads GitHub's latest published release `tag_name` and updates the navbar to:
```text
Release vX.Y.Z
```
The button also updates to the exact release `html_url`.

The result is cached in the browser for one hour. If GitHub is unavailable or rate-limited, the button safely remains `Release` and still points to:
```text
https://github.com/lily-studios/Reactily/releases/latest
```

## Navbar ownership

Moonwave owns the built-in `API` and `GitHub` navbar items.

- `/api` is a real custom page in `pages/api.js`
- `GitHub` comes from `gitRepoUrl`
- `Release` is the only custom right-side project button

Do not add another GitHub navbar item manually, and do not create a second API landing document under `docs/api.md`.
